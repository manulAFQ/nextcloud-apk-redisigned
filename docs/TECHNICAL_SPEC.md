# Техническое задание: Nextcloud Gallery Android

## 1. Назначение

Разработать самостоятельное Android-приложение для семейного фотоархива, работающего с существующим сервером Nextcloud исключительно внутри локальной сети. Интерфейс должен быть визуально и поведенчески близок к Google Фото, но не копировать его бренд, логотипы и графические материалы.

Адрес сервера вводит пользователь при первом запуске; приложение не содержит предустановленного адреса.

Пользователи Nextcloud имеют отдельные учётные записи. Данные одного пользователя не должны отображаться другому, если владелец явно не предоставил общий доступ средствами Nextcloud.

Существующий сервер считается внешней неизменяемой системой. Проект не должен менять его установку, конфигурацию или сетевое окружение. Все функции приложения реализуются на стороне Android-клиента и работают с правами обычного пользователя Nextcloud.

Nextcloud является единственным доверенным контуром и источником решений о безопасности.
Android-приложение считается обычным недоверенным клиентом и не реализует собственную
систему пользователей, ролей, разрешений или разграничения доступа.

## 2. Границы проекта

### Входит в проект

- отдельное Android-приложение с собственным названием, иконкой и package ID;
- вход в существующую учётную запись Nextcloud;
- фотолента, сгруппированная по датам;
- просмотр фотографий и видео;
- папки и альбомы;
- ручная и автоматическая загрузка медиафайлов;
- устойчивая очередь загрузок с продолжением после обрыва;
- работа через Wi-Fi локальной сети;
- локальное кеширование метаданных и миниатюр.

### Не входит в первую версию

- доступ через интернет;
- изменение конфигурации роутера;
- собственная регистрация пользователей;
- сервер распознавания лиц и объектов;
- редактор фото и видео;
- резервное копирование остальных типов файлов;
- публикация в Google Play.

### Запрещённые изменения инфраструктуры

- изменение конфигурации Nextcloud и веб-сервера;
- установка приложений, модулей, фоновых служб или дополнительного API на сервер;
- изменение контейнеров, systemd-служб, базы данных и PHP-конфигурации;
- прямой доступ приложения к базе данных или каталогу данных Nextcloud;
- использование root-доступа или учётной записи администратора Nextcloud;
- изменение настроек роутера, DHCP, Wi-Fi, портов и межсетевого экрана;
- открытие сервера в интернет ради работы мобильного приложения;
- хранение в проекте серверных паролей, ключей и резервных копий конфигурации.

Если функция требует изменения сервера, она исключается либо заменяется клиентской реализацией. Отсутствующая серверная возможность не является основанием ослаблять защиту инфраструктуры.

## 3. Общая архитектура

Отдельный прикладной сервер создавать не требуется. Серверная часть — уже установленный Nextcloud. Android-клиент взаимодействует с ним напрямую, не устанавливая на сервер никаких компонентов и не изменяя его настройки.

```text
Android UI (Compose)
        |
ViewModel / Use Cases
        |
Repository + локальная Room DB
        |
Nextcloud Android Library / WebDAV / OCS API
        |
Nextcloud в локальной сети
        |
Каталог данных на диске 500 ГБ
```

Архитектура приложения: многослойная, с разделением на `presentation`, `domain` и `data`. Данные сервера считаются первичным источником, Room используется как локальный индекс и кеш.

## 4. Серверная часть (backend)

### 4.1. Основа

Используется действующий Nextcloud. Собственная база пользователей, хранилище или REST-сервер не создаются. Приложение использует уже доступные функции сервера:

- аутентификацию и сессии;
- разграничение прав пользователей;
- хранение оригиналов файлов;
- WebDAV-операции;
- общие папки и ссылки;
- генерацию миниатюр и preview;
- квоты и контроль свободного места;
- журналирование серверных ошибок.

Любая операция разрешается или запрещается только сервером Nextcloud. Скрытие кнопки
в интерфейсе не считается защитой, а локальные метаданные не дают дополнительных прав.
Клиент передаёт серверу пользовательский app password, выполняет документированный API
и обрабатывает полученный ответ, не дублируя серверную авторизацию.

### 4.2. Интерфейсы сервера

Клиент должен использовать официальную Nextcloud Android Library там, где она покрывает необходимые операции. Для остальных операций допускаются документированные интерфейсы Nextcloud:

- Login Flow v2 — безопасное добавление учётной записи;
- WebDAV — список файлов, загрузка, скачивание, перемещение и удаление;
- OCS API — возможности сервера, сведения о пользователе, квота и общий доступ;
- Activity API — события аккаунта, если оно доступно текущему пользователю;
- WebDAV trashbin — удалённые файлы, если сервер объявляет поддержку корзины;
- Preview API — серверные миниатюры;
- ETag — определение изменений без повторного скачивания файлов.

Жёсткая привязка к конкретной версии Nextcloud запрещена. При подключении приложение запрашивает capabilities и включает только поддерживаемые функции.

### 4.3. Размещение файлов

По умолчанию автоматическая загрузка выполняется в каталог:

`Photos/Auto Upload/<название устройства>/<год>/<месяц>/`

Путь можно изменить в настройках. Оригинальное имя файла сохраняется. При совпадении имени приложение не должно молча перезаписывать существующий файл: используется проверка содержимого и безопасное уникальное имя.

### 4.4. Надёжная загрузка

- Файл считается переданным только после успешного ответа сервера и проверки размера/метаданных.
- Состояние каждой задачи сохраняется локально.
- После потери Wi-Fi, остановки приложения или перезагрузки телефона задача продолжается либо безопасно запускается заново.
- Для крупных файлов используется chunked upload, если сервер его поддерживает.
- Повторные попытки выполняются с увеличивающейся задержкой.
- Один и тот же файл не должен загружаться повторно после успешной передачи.
- Ошибки нехватки места, авторизации и недоступности сервера показываются отдельно.

### 4.5. Ограничения существующего сервера

Приложение принимает сервер таким, какой он есть, и только проверяет доступные пользователю возможности. Проверка является строго read-only и не должна автоматически исправлять конфигурацию.

- Адрес Nextcloud задаётся пользователем и хранится только в защищённом локальном хранилище приложения.
- Клиент не меняет автозапуск, сетевые интерфейсы, IP-адрес и порты сервера.
- Клиент не меняет `trusted_domains`, квоты, права каталогов и расположение данных.
- Клиент не управляет диском 500 ГБ и не обращается к нему напрямую.
- При недоступной функции клиент показывает понятное ограничение и продолжает работать в доступном режиме.

Поскольку используется HTTP, трафик не защищён от перехвата внутри локальной сети. Клиент разрешает незашифрованное соединение только с явно указанным локальным адресом, не принимает автоматически перенаправление на внешний узел и предупреждает пользователя при смене адреса сервера. Исправление или усиление защиты самого сервера не входит в проект.

## 5. Android-клиент (frontend)

### 5.1. Технологии

- Kotlin;
- Jetpack Compose, Material 3;
- Navigation Compose;
- MVVM или однонаправленный поток состояния;
- Kotlin Coroutines и Flow;
- официальная Nextcloud Android Library;
- Room;
- WorkManager;
- Hilt;
- Coil;
- Android Photo Picker;
- Media3 для воспроизведения видео.

Минимальную версию Android определить при инициализации проекта после проверки используемой версии библиотеки. Целевая версия SDK — актуальная стабильная на момент сборки.

### 5.2. Основная навигация

Информационная архитектура сохраняет удачные пользовательские сценарии официального
Nextcloud-клиента, но не копирует его внешний вид. Конкретная компоновка, стиль и
расположение пунктов будут проработаны на отдельном этапе дизайна.

В верхнем уровне навигации должны быть доступны:

1. **События** — история значимых изменений и действий пользователя.
2. **Медиа** — общая хронологическая лента фотографий и видео.
3. **Альбомы** — папки и пользовательские подборки.
4. **Состояние передачи** — активные, завершённые и ошибочные передачи.
5. **На устройстве** — локальные фотографии и видео, включая ещё не переданные.
6. **Удалённые файлы** — доступ к штатной корзине Nextcloud без обхода серверных правил.
7. **Синхронизация** — отдельный самостоятельный пункт, а не подраздел настроек.

**Настройки** остаются отдельным служебным разделом. В них находятся параметры
аккаунта, сети, батареи, кеша и поведения приложения, но не текущий статус и управление
синхронизацией. Файловый менеджер не является главным экраном и может быть добавлен
позднее.

### 5.3. Экран подключения

- поле адреса сервера с предзаполненным локальным адресом;
- проверка доступности `/status.php`;
- понятные состояния: сервер найден, нет Wi-Fi, сервер выключен, неверный адрес, требуется вход;
- вход через Login Flow v2 или совместимый механизм официальной библиотеки;
- безопасное хранение токена в Android Keystore/AccountManager;
- поддержка нескольких аккаунтов предусматривается архитектурой, но в MVP активен один аккаунт одновременно.

Сценарий входа должен сохранить понятную механику официального клиента Nextcloud:
пользователь вводит адрес сервера, проходит Login Flow v2 в браузере и возвращается в
приложение уже с добавленным аккаунтом. Собственная форма для ввода и сохранения
обычного пароля Nextcloud не создаётся.

Пароль пользователя не сохраняется в открытом виде и не записывается в логи.

### 5.4. Фотолента

- адаптивная сетка миниатюр;
- группировка по дням и месяцам;
- плавная прокрутка больших библиотек;
- быстрый переход по датам;
- фото и видео визуально различимы;
- индикатор длительности видео;
- выбор одного или нескольких элементов долгим нажатием;
- обновление жестом вниз;
- состояния загрузки, пустой библиотеки и ошибки;
- показ кешированных данных при временной недоступности сервера.

Сортировка выполняется прежде всего по EXIF `DateTimeOriginal`, затем по времени создания/изменения файла.

### 5.5. Просмотр медиа

- полноэкранный просмотр;
- перелистывание соседних элементов;
- масштабирование фото жестами;
- воспроизведение видео;
- сведения о файле;
- скачать на устройство;
- удалить с подтверждением;
- переместить в альбом/папку;
- системная отправка в другое приложение;
- отображение оригинала только по запросу, до этого используется preview.

### 5.6. Альбомы

В MVP альбом соответствует папке Nextcloud. Должны поддерживаться:

- список альбомов;
- создание папки-альбома;
- добавление выбранных файлов;
- переименование;
- удаление с подтверждением;
- отображение обложки и количества элементов.

Виртуальные альбомы без перемещения файлов рассматриваются после MVP.

### 5.7. Ручная загрузка

- выбор фото и видео через системный Photo Picker;
- выбор целевого альбома;
- очередь с прогрессом каждого файла и общим прогрессом;
- пауза, отмена и повтор ошибки;
- работа в фоне с системным уведомлением;
- сохранение очереди после перезапуска приложения.

### 5.8. Автоматическая загрузка

- включается пользователем отдельно;
- выбор папок устройства: камера, скриншоты и другие;
- режим «только Wi-Fi» включён по умолчанию;
- дополнительное ограничение: загружать только при подключении к выбранному SSID;
- настройка зарядки и минимального заряда батареи;
- возможность включить или исключить видео;
- отслеживание уже переданных элементов;
- уведомление об ошибке после исчерпания повторных попыток.

Android может скрывать SSID без разрешения геолокации. Приложение должно объяснять это перед запросом разрешения и работать без SSID-фильтра, если пользователь его не предоставил.

### 5.9. Синхронизация и состояние передачи

Это два разных пользовательских сценария:

- **Состояние передачи** показывает отдельные загрузки и скачивания, их прогресс,
  скорость, ошибки, паузу, отмену и повтор.
- **Синхронизация** показывает охват локальных папок, время последней сверки,
  ожидающие изменения, сетевые ограничения и позволяет запустить сверку вручную.

Экран синхронизации является отдельным пунктом основной навигации. Параметры политики
могут переиспользовать хранилище настроек, но пользователь не должен искать запуск,
прогресс или ошибку синхронизации внутри экрана настроек.

### 5.10. Визуальные требования

- светлая и тёмная темы;
- крупный медиаконтент, минимум служебного текста;
- Material 3 и системные динамические цвета как опция;
- скруглённые карточки и аккуратные анимации без ущерба скорости;
- отсутствие визуальных материалов и товарных знаков Google Фото;
- отсутствие визуальных материалов Nextcloud, кроме случаев, разрешённых правилами бренда;
- доступность: масштабирование текста, content descriptions, достаточный контраст.

## 6. Локальные данные

Room хранит:

- аккаунты без открытых паролей;
- метаданные удалённых медиафайлов;
- ETag и состояние синхронизации;
- очередь загрузок;
- идентификаторы локальных файлов, уже переданных на сервер;
- пользовательские настройки.

Оригиналы удалённых файлов постоянно не кешируются. Кеш миниатюр имеет ограничение размера и очищается автоматически.

## 7. Граница ответственности за безопасность

За аутентификацию, авторизацию, разделение аккаунтов, доступ к каталогам, квоты,
корзину и допустимость файловых операций полностью отвечает Nextcloud. Приложение:

- не создаёт собственные роли, ACL, пароли, правила доступа или механизм шифрования
  серверных файлов;
- не считает локальную Room DB источником прав и не разрешает операцию на основании кеша;
- не пытается обходить ответ `401`, `403`, квоту или другое ограничение сервера;
- не изменяет и не «усиливает» конфигурацию Nextcloud, ОС сервера или роутера;
- не заявляет защиту сетевого трафика: при текущем HTTP она определяется фактической
  конфигурацией локальной сети и Nextcloud.

На Android остаётся только обязательная клиентская гигиена, а не отдельный контур
безопасности:

- Никакой аналитики, рекламы и сторонних облачных сервисов в MVP.
- Сетевые запросы направляются только на выбранный сервер Nextcloud.
- Обычный пароль не хранится; выданный Nextcloud app password не записывается в логи,
  Room, crash reports или резервную копию и хранится стандартными средствами Android.
- Очистка аккаунта удаляет локальные токены, БД и кеш этого аккаунта, но не серверные файлы.
- Удаление файла с сервера требует явного действия и подтверждения.
- В production-сборке отключено подробное сетевое логирование.

## 8. Производительность

- Первая полезная отрисовка кешированной фотоленты — до 2 секунд на обычном устройстве.
- Прокрутка не должна загружать оригиналы фотографий.
- Индексация и сетевые операции не выполняются в главном потоке.
- Список должен корректно работать минимум с 50 000 элементов за счёт постраничной загрузки.
- Память не должна удерживать полноразмерные изображения вне активного просмотрщика.

## 9. Обработка ошибок

Пользователь получает конкретное сообщение и действие:

- сервер недоступен — повторить;
- телефон не в выбранной Wi-Fi сети — открыть настройки сети;
- сессия истекла — войти повторно;
- закончилось место — показать доступную квоту;
- файл изменился или уже существует — выбрать безопасный вариант;
- передача прервана — оставить задачу в очереди и продолжить автоматически;
- сервер не поддерживает функцию — скрыть её или показать объяснение.

## 10. Сборка и поставка

- Репозиторий Gradle с воспроизводимой debug-сборкой.
- Отдельные `debug` и `release` варианты.
- Адрес сервера не вшивается в исходный код как единственно допустимый; его можно изменить.
- Для домашней установки выпускается подписанный APK.
- Ключ подписи хранится вне Git и резервируется владельцем.
- Обновление APK поверх установленной версии возможно только тем же ключом.
- Лицензии всех зависимостей отображаются в разделе «О приложении».

## 11. Этапы разработки

### Этап 0. Проверка совместимости без изменения сервера

- проверить `status.php`, WebDAV и preview с телефона;
- определить доступные API и capabilities с правами обычного пользователя;
- получить доступную пользователю квоту через API без проверки файловой системы;
- проверить загрузку большого тестового файла с возобновлением.

Все проверки этапа выполняются без административных учётных данных и без изменений конфигурации сервера, операционной системы или роутера.

### Этап 1. MVP

- каркас проекта;
- подключение и вход;
- получение списка медиа;
- фотолента;
- полноэкранный просмотр фото;
- ручная загрузка;
- постоянная очередь и автоматический повтор;
- debug APK для установки на телефон.

### Этап 2. Основной релиз

- видео;
- альбомы;
- удаление и перемещение;
- автозагрузка камеры;
- настройки сети, батареи и кеша;
- release APK с собственной подписью.

### Этап 3. Улучшения

- несколько аккаунтов;
- общий доступ;
- виртуальные альбомы и избранное;
- поиск;
- локальная карта или группировка по местам;
- локальное распознавание лиц без отправки данных наружу.

## 12. Критерии приёмки MVP

MVP считается готовым, если:

1. Пользователь устанавливает APK и входит в свой аккаунт на локальном Nextcloud.
2. Приложение отображает фото из заданного серверного каталога в хронологической сетке.
3. Фото открывается полноэкранно без предварительного скачивания всех оригиналов.
4. Выбранные на телефоне файлы загружаются в целевую папку.
5. При отключении Wi-Fi незавершённая загрузка не теряется и продолжается после восстановления связи.
6. После перезапуска приложения очередь сохраняется.
7. Пользователь другого аккаунта не видит чужие файлы без предоставленного доступа.
8. Приложение не обращается к внешним облачным или аналитическим сервисам.
9. Ошибки авторизации, недоступности сервера и нехватки места различаются в интерфейсе.
10. Debug APK устанавливается и проходит проверку на реальном телефоне в домашней сети.

## 13. Открытые решения перед реализацией

Перед началом разработки потребуется выбрать:

- название приложения и package ID;
- минимальную поддерживаемую версию Android;
- точный корневой каталог фототеки на сервере;
- нужен ли в первой версии просмотр всех папок или только `Photos`;
- допустимо ли удаление серверных файлов из приложения;
- имя Wi-Fi сети для режима «только домашняя сеть»;
- иконку и базовую цветовую тему.
